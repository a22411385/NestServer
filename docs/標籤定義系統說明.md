## 系統概述

### 設計理念

標籤定義系統允許你在 Google Sheets 中集中管理所有標籤，包括：
- 標籤的顯示名稱和描述
- 標籤的類別和顏色
- 標籤的層級關係
- 標籤的啟用狀態

### 優勢

✅ **集中管理**: 所有標籤定義集中在一個地方  
✅ **元數據豐富**: 每個標籤可以包含顏色、圖示、描述等  
✅ **驗證機制**: 可以驗證屬性使用的標籤是否合法  
✅ **UI 友好**: 前端可以直接讀取標籤資訊顯示  
✅ **層級支援**: 支援標籤之間的父子關係

## 資料結構

### TypeScript 類型定義

```typescript
/**
 * 標籤類別
 */
export type TagCategory = 
    | 'element'      // 元素類型
    | 'ailment'      // 異常狀態
    | 'attack_type'  // 攻擊類型
    | 'weapon_type'  // 武器類型
    | 'function'     // 功能類型
    | 'category';    // 分類標籤

/**
 * 標籤定義
 */
export interface TagDefinition {
    id: string;              // 標籤ID (fire, ailment, melee)
    displayName: string;     // 顯示名稱（中文）
    description: string;     // 標籤說明
    category: TagCategory;   // 標籤類別
    color?: string;          // UI 顯示顏色 (#FF0000)
    icon?: string;           // 圖示名稱或路徑
    parent?: string;         // 父級標籤ID（支援層級關係）
    enabled: boolean;        // 是否啟用
}
```

## CSV 欄位說明

### 完整欄位列表

| 欄位名稱 | 類型 | 必填 | 說明 | 範例 |
|---------|------|------|------|------|
| `id` | string | ✅ | 標籤唯一識別碼 | `fire`, `burn`, `melee` |
| `displayName` | string | ✅ | 顯示名稱（中文） | `火元素`, `燃燒`, `近戰` |
| `description` | string | ✅ | 標籤說明 | `火元素相關效果和傷害` |
| `category` | TagCategory | ✅ | 標籤類別 | `element`, `ailment`, `attack_type` |
| `color` | string | ❌ | UI 顯示顏色（十六進制） | `#FF4500`, `#00CED1` |
| `icon` | string | ❌ | 圖示名稱或路徑 | `flame`, `snowflake`, `sword` |
| `parent` | string | ❌ | 父級標籤ID | `fire`, `cold`, `weapon` |
| `enabled` | boolean | ✅ | 是否啟用 | `TRUE`, `FALSE` |

### 欄位詳細說明

#### 1️⃣ id（標籤ID）
- **格式**: 小寫英文，底線分隔
- **唯一性**: 必須在整個系統中唯一
- **命名規範**: 簡潔、語意清晰
- **範例**: `fire`, `attack_speed`, `critical_damage`

#### 2️⃣ displayName（顯示名稱）
- **用途**: UI 中顯示的標籤名稱
- **語言**: 中文或其他本地化語言
- **範例**: `火元素`, `攻擊速度`, `暴擊傷害`

#### 3️⃣ description（描述）
- **用途**: 說明標籤的作用和適用範圍
- **建議長度**: 10-30 字
- **範例**: `火元素相關效果和傷害`, `增加攻擊速度的屬性`

#### 4️⃣ category（類別）
- **可選值**:
  - `element`: 元素類型（火、冰、雷等）
  - `ailment`: 異常狀態（燃燒、冰凍等）
  - `attack_type`: 攻擊類型（近戰、遠程等）
  - `weapon_type`: 武器類型（劍、弓、法杖等）
  - `function`: 功能類型（傷害、輔助等）
  - `category`: 分類標籤（通用分類）

#### 5️⃣ color（顏色）
- **格式**: 十六進制顏色碼 `#RRGGBB`
- **用途**: UI 中標籤的顯示顏色
- **範例**: 
  - 火元素: `#FF4500` (橙紅色)
  - 冰元素: `#00CED1` (青色)
  - 物理: `#8B4513` (棕色)

#### 6️⃣ icon（圖示）
- **格式**: 圖示名稱或路徑
- **用途**: UI 中顯示的圖示
- **範例**: `flame`, `snowflake`, `bolt`, `sword`

#### 7️⃣ parent（父級標籤）
- **用途**: 建立標籤層級關係
- **格式**: 父級標籤的 ID
- **範例**: 
  - `burn` 的 parent 是 `fire`
  - `freeze` 的 parent 是 `cold`
  - `sword` 的 parent 是 `weapon`

#### 8️⃣ enabled（啟用狀態）
- **用途**: 控制標籤是否可用
- **值**: `TRUE` 或 `FALSE`
- **建議**: 棄用的標籤設為 `FALSE` 而非刪除

## 層級關係

### 什麼是層級關係？

層級關係允許標籤之間建立父子關係，例如：
- `burn` 是 `fire` 的子標籤
- `freeze` 是 `cold` 的子標籤
- `sword` 是 `weapon` 的子標籤

### 如何使用？

```csv
id,displayName,parent
fire,火元素,
burn,燃燒,fire
```

在這個例子中：
- `fire` 沒有父級（頂層標籤）
- `burn` 的父級是 `fire`（子標籤）

### 查詢優勢

使用層級關係，可以實現智能查詢：

```typescript
// 查詢所有火元素相關的屬性
// 會同時匹配 fire 和 burn
TagMatcher.findByParent('fire')
// 返回: ['fire', 'burn', ...]

// 獲取標籤的完整路徑
TagMatcher.getTagPath('burn')
// 返回: ['elemental', 'fire', 'burn']
```

## 使用範例

### 範例 1: 元素標籤定義

```csv
id,displayName,description,category,color,icon,parent,enabled
fire,火元素,火元素相關效果和傷害,element,#FF4500,flame,,TRUE
burn,燃燒,持續火焰傷害,ailment,#FF6347,fire,fire,TRUE
```

**說明**:
- `fire` 是元素標籤，顏色為橙紅色
- `burn` 是異常狀態標籤，父級是 `fire`
- 兩者都啟用

### 範例 2: 攻擊類型標籤

```csv
id,displayName,description,category,color,icon,parent,enabled
projectile,投射物,與投射物相關,attack_type,#32CD32,arrow,,TRUE
pierce,穿透,穿透敵人,attack_type,#708090,arrow-right,,TRUE
```

**說明**:
- 兩個獨立的攻擊類型標籤
- 沒有父子關係

### 範例 3: 武器類型層級

```csv
id,displayName,description,category,color,icon,parent,enabled
weapon,武器,通用武器標籤,weapon_type,#696969,sword,,TRUE
sword,劍,劍類武器,weapon_type,#C0C0C0,sword,weapon,TRUE
axe,斧,斧頭類武器,weapon_type,#8B4513,axe,weapon,TRUE
```

**說明**:
- `weapon` 是頂層標籤
- `sword` 和 `axe` 都繼承自 `weapon`

## 最佳實踐

### ✅ 命名規範

1. **ID 使用小寫**: `fire`, `attack_speed`, 不要用 `Fire`, `AttackSpeed`
2. **描述要清晰**: 說明標籤的用途和適用範圍
3. **顏色要一致**: 同類標籤使用相近的顏色

### ✅ 層級設計

1. **不要過深**: 層級不超過 3 層（祖父-父-子）
2. **語意清晰**: 父子關係要符合邏輯
3. **避免循環**: 不要讓標籤互為父子

### ✅ 維護建議

1. **不要刪除**: 棄用標籤時設為 `enabled=FALSE`
2. **定期審查**: 檢查未使用的標籤
3. **文檔同步**: 更新標籤時同步更新文檔

### ⚠️ 常見錯誤

```csv
❌ id,displayName,parent
❌ Fire,火元素,        # ID 不應該大寫
❌ fire,火,,Fire       # parent 應該用小寫 ID

✅ id,displayName,parent
✅ fire,火元素,
✅ burn,燃燒,fire
```

## 整合流程

### 1️⃣ Google Sheets 配置

1. 建立 `TagDefinitions` 工作表
2. 填入標籤定義資料
3. 確保每個標籤都有唯一的 ID

### 2️⃣ 資料同步

```typescript
// 在 GoogleSheetCache.ts 中載入標籤定義
async loadTagDefinitions() {
    const response = await this.sheets.spreadsheets.values.get({
        spreadsheetId: this.spreadsheetId,
        range: 'TagDefinitions!A2:H',
    });
    
    const rows = response.data.values || [];
    const tagDefs: TagDefinition[] = rows.map(row => ({
        id: row[0],
        displayName: row[1],
        description: row[2],
        category: row[3] as TagCategory,
        color: row[4] || undefined,
        icon: row[5] || undefined,
        parent: row[6] || undefined,
        enabled: row[7] === 'TRUE'
    }));
    
    return tagDefs;
}
```

### 3️⃣ 驗證屬性標籤

```typescript
// 驗證屬性使用的標籤是否合法
function validatePropertyTags(
    property: WeaponPropertyDefinition,
    validTags: TagDefinition[]
): boolean {
    const tagIds = property.tags.split(',').map(t => t.trim());
    const validTagIds = validTags
        .filter(t => t.enabled)
        .map(t => t.id);
    
    return tagIds.every(tag => validTagIds.includes(tag));
}
```
