## 🎯 技術決策

### 1. JSON 序列化方案
**為什麼選擇 JSON 而非 Schema 類？**
- ✅ 快速實施（無需建立額外的 Schema 類）
- ✅ 客戶端解析簡單
- ✅ 保持靈活性（未來可優化）
- ✅ 減少 Schema 同步負擔

### 2. 向下相容
**保留舊版 applyProperties()**
- 避免破壞現有代碼
- 逐步遷移到新系統
- 標記為 @deprecated

### 3. 欄位命名優化
**重命名原因：**
- `effectProperties` 更明確表示「效果屬性」
- `modifiers` 和 `bonuses` 更簡潔
- 與業務邏輯對應更清晰
