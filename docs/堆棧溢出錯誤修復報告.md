# 堆棧溢出錯誤修復報告

📅 **修復日期**: 2025-11-01  
🐛 **錯誤**: Maximum call stack size exceeded  
🎯 **觸發點**: GameControlHandler.startGame → Hero初始化 → 武器裝備

---

## 🔍 問題分析

### 錯誤堆棧追蹤

```
startGame()
  → PlayerManager.initializeAllHeroes()
    → Hero.adddWeapon('iron_sword')
      → Hero.equip(weaponId)
        → Hero.recalculateAllStats()
          → Hero.updateWeaponAttributeBonuses()
            → Hero.applyEquipmentBonus(bonuses)
              → Hero.recalculateAllStats()  ❌ 循環！
                → 無限循環...
```

### 問題根源

在 `Hero.ts` 中發現兩個相互調用的方法形成了**無限循環**：

1. **recalculateAllStats() (第 263 行)**
   ```typescript
   public recalculateAllStats(): void {
       // 🔄 0. 首先收集所有裝備武器的屬性加成
       this.updateWeaponAttributeBonuses();  // ← 調用更新武器加成
       // ... 其他計算 ...
   }
   ```

2. **updateWeaponAttributeBonuses() (第 318 行)**
   ```typescript
   private updateWeaponAttributeBonuses(): void {
       // ... 收集武器加成 ...
       
       // 🆕 應用收集到的屬性加成
       if (allBonuses.length > 0) {
           this.applyEquipmentBonus(allBonuses);  // ← 調用應用加成
       }
   }
   ```

3. **applyEquipmentBonus() (第 463 行)**
   ```typescript
   public applyEquipmentBonus(bonuses: AttributeBonus[]): void {
       // ... 應用加成 ...
       
       // 重新計算最終屬性
       this.recalculateAllStats();  // ❌ 又調用回去了！
   }
   ```

## ✅ 修復方案

### 方案：分離屬性收集與應用邏輯

**核心思想**：
- `updateWeaponAttributeBonuses()` **只負責收集和直接應用**屬性，不再觸發完整重算
- `recalculateAllStats()` 負責調用收集，然後進行最終計算
- **避免嵌套的 recalculateAllStats() 調用**

### 修改 1: 優化 updateWeaponAttributeBonuses()

**位置**: `Hero.ts:318-357`

```typescript
private updateWeaponAttributeBonuses(): void {
    // 重置武器屬性加成
    this.weaponStr = 0;
    this.weaponInt = 0;
    this.weaponAgi = 0;
    this.weaponVit = 0;

    // ✅ 同時重置裝備加成（避免累積）
    this.equipmentHpBonus = 0;
    this.equipmentAttackBonus = 0;
    this.equipmentMpBonus = 0;
    this.hpMultiplier = 1.0;
    this.attackMultiplier = 1.0;
    this.speedMultiplier = 1.0;
    this.mpMultiplier = 1.0;

    // 🔧 修復 Bug #1：直接遍歷 weaponInventory
    // 原代碼：for (const weapon of this.weaponInventory)
    //           const weaponSchema = this.findWeaponSchemaById(weapon.uniqueId);
    // 問題：weapon 本身就是 WeaponSchema，不需要再查找
    for (const weaponSchema of this.weaponInventory) {
        // 只處理已裝備的武器
        if (!weaponSchema.isEquipped) {
            continue;
        }

        // 舊版屬性（向下相容）
        this.weaponStr += weaponSchema.str || 0;
        this.weaponInt += weaponSchema.int || 0;
        this.weaponAgi += weaponSchema.agi || 0;
        this.weaponVit += weaponSchema.vit || 0;

        // 🆕 新版屬性加成系統 - 直接計算，不調用 applyEquipmentBonus（避免循環）
        try {
            const bonuses = weaponSchema.getBonuses();
            if (bonuses && bonuses.length > 0) {
                // ✅ 修復 Bug #2：直接應用屬性加成，不觸發 recalculateAllStats
                this.applyBonusesDirectly(bonuses);
            }
        } catch (error) {
            // 靜默處理，不影響舊武器
        }
    }
}
```

**關鍵修改**：
1. ✅ 修復 Bug #1：移除冗餘的 `findWeaponSchemaById` 調用
2. ✅ 修復 Bug #2：使用新方法 `applyBonusesDirectly()` 替代 `applyEquipmentBonus()`
3. ✅ 在方法開始時重置所有加成屬性（避免累積錯誤）

### 修改 2: 新增 applyBonusesDirectly() 方法

**位置**: `Hero.ts:359-402`

```typescript
/**
 * 🆕 直接應用屬性加成（不觸發重算）
 * 用於 updateWeaponAttributeBonuses 中避免循環調用
 */
private applyBonusesDirectly(bonuses: any[]): void {
    // 檢查是否為新版屬性加成（有 affectedStat 欄位）
    const isNewSystem = bonuses.some(b => b.affectedStat);

    if (isNewSystem) {
        // 🆕 新版：配置驅動的屬性加成系統
        // 按 affectedStat 分組
        const bonusesByAffectedStat = new Map<string, any[]>();

        for (const bonus of bonuses) {
            if (!bonus.enabled) continue;

            const affectedStat = bonus.affectedStat;
            if (!affectedStat) continue;

            if (!bonusesByAffectedStat.has(affectedStat)) {
                bonusesByAffectedStat.set(affectedStat, []);
            }
            bonusesByAffectedStat.get(affectedStat)!.push(bonus);
        }

        // ✅ 對每個屬性應用 POE 規則計算（複用現有邏輯）
        for (const [affectedStat, statBonuses] of bonusesByAffectedStat) {
            this.applyBonusToStat(affectedStat, statBonuses);
        }
    } else {
        // 舊版：hardcode 的屬性加成
        for (const bonus of bonuses) {
            this.equipmentHpBonus += (bonus as any).hpBonus || 0;
            this.equipmentAttackBonus += (bonus as any).attackBonus || 0;
            this.equipmentMpBonus += (bonus as any).mpBonus || 0;
            this.hpMultiplier *= (1 + ((bonus as any).hpMultiplier || 0));
            this.attackMultiplier *= (1 + ((bonus as any).attackMultiplier || 0));
            this.speedMultiplier *= (1 + ((bonus as any).speedMultiplier || 0));
            this.mpMultiplier *= (1 + ((bonus as any).mpMultiplier || 0));
        }
    }
}
```

**設計要點**：
- ✅ **不調用** `recalculateAllStats()`（關鍵！）
- ✅ 複用現有的 `applyBonusToStat()` 方法（POE 規則計算）
- ✅ 支援新舊兩種屬性系統

## 🎯 修復總結

### 解決的問題

1. ✅ **無限循環調用**
   - 修復前：`recalculateAllStats()` ↔ `applyEquipmentBonus()` 循環
   - 修復後：單向調用，無循環

2. ✅ **冗餘的武器查找**
   - 修復前：`for (const weapon of inventory) { findWeaponSchemaById(weapon.uniqueId) }`
   - 修復後：`for (const weaponSchema of inventory)`

3. ✅ **屬性累積錯誤**
   - 修復前：屬性加成可能在多次調用中累積
   - 修復後：每次重算前清零所有加成

### 影響範圍

- ✅ **不影響現有功能**：只修改內部調用邏輯
- ✅ **向下相容**：保留舊版屬性系統支援
- ✅ **性能優化**：減少冗餘查找和重複計算

### 技術要點

1. **職責分離**
   - `recalculateAllStats()` - 完整重算，可調用其他方法
   - `updateWeaponAttributeBonuses()` - 只負責收集和直接應用，不觸發重算
   - `applyBonusesDirectly()` - 純計算方法，無副作用

2. **防禦性編程**
   - 所有加成屬性在計算前清零
   - try-catch 保護新屬性系統，不影響舊武器
   - 靜默處理錯誤，確保系統穩定

3. **可維護性**
   - 清晰的調用鏈，無循環依賴
   - 方法職責單一，易於理解和修改
   - 詳細的註釋說明關鍵邏輯
