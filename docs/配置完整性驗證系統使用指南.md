## 功能概述

配置完整性驗證系統用於自動檢查 Google Sheets 配置表之間的參照關係是否正確，確保：
- ✅ 所有屬性加成參照的都是有效的屬性
- ✅ 所有武器詞綴參照的都是有效的屬性
- ✅ 所有武器配置參照的都是存在的加成和詞綴

---

## 驗證項目

### 1️⃣ **AttributeBonus.affectedStat → WeaponStatConfig.attributeId**
驗證所有屬性加成的 `affectedStat` 欄位是否參照了有效的屬性 ID。

**範例錯誤：**
```
❌ AttributeBonus "strength" 的 affectedStat "strength" 不存在於 WeaponStatConfig 中
```

**修正方式：**
- 在 `WeaponStatConfigs` 表中新增 `strength` 屬性定義
- 或修改 `AttributeBonus` 表中 `strength` 的 `affectedStat` 為有效的屬性 ID

---

### 2️⃣ **WeaponModifier.affectedStat → WeaponStatConfig.attributeId**
驗證所有武器詞綴的 `affectedStat` 欄位是否參照了有效的屬性 ID。

**範例錯誤：**
```
❌ WeaponModifier "splash_damage" 的 affectedStat "damage" 不存在於 WeaponStatConfig 中
```

**修正方式：**
- 將 `affectedStat` 從 `"damage"` 改為 `"weapon_damage"` (正確的屬性 ID)
- 或在 `WeaponStatConfigs` 中新增 `damage` 屬性定義

---

### 3️⃣ **WeaponConfig.bonuses → AttributeBonus.id**
驗證武器配置的 `bonuses` 欄位是否參照了存在的屬性加成。

**範例錯誤：**
```
❌ WeaponConfig "fireball" 參照了不存在的 AttributeBonus "unknown_bonus"
```

**修正方式：**
- 從 `WeaponConfig.bonuses` 中移除 `"unknown_bonus"`
- 或在 `AttributeBonus` 表中新增 `unknown_bonus` 定義

---

### 4️⃣ **WeaponConfig.modifiers → WeaponModifier.id**
驗證武器配置的 `modifiers` 欄位是否參照了存在的武器詞綴。

**範例錯誤：**
```
❌ WeaponConfig "sword" 參照了不存在的 WeaponModifier "super_slash"
```

**修正方式：**
- 從 `WeaponConfig.modifiers` 中移除 `"super_slash"`
- 或在 `WeaponModifiers` 表中新增 `super_slash` 定義

### 方式 2：在代碼中使用

```typescript
import { ConfigManager } from '@/Game/Managers/ConfigManager';

// 執行完整驗證
const result = ConfigManager.validateConfigs();

if (!result.isValid) {
    console.error('配置驗證失敗！');
    console.error('錯誤:', result.errors);
    console.error('警告:', result.warnings);
}
```

**進階用法：**
```typescript
import { ConfigValidationService } from '@/Game/Services/ConfigValidationService';

// 1. 完整驗證
const fullResult = ConfigValidationService.validateAllConfigs();

// 2. 只驗證 AttributeBonus
const bonusResult = ConfigValidationService.validateAttributeBonusConfig();

// 3. 只驗證 WeaponModifier
const modifierResult = ConfigValidationService.validateWeaponModifierConfig();
```

### 方式 3：整合到伺服器啟動流程

在 `main.ts` 中添加驗證：

```typescript
import { ConfigManager } from '@/Game/Managers/ConfigManager';

async function bootstrap() {
    // ... 其他初始化代碼 ...

    // 🔍 驗證配置完整性
    try {
        const result = ConfigManager.validateConfigs(false); // 不拋出錯誤
        if (!result.isValid) {
            console.warn('⚠️  配置驗證發現錯誤，但伺服器仍會啟動');
            console.warn(`錯誤數量: ${result.errors.length}`);
        }
    } catch (error) {
        console.error('❌ 配置驗證失敗:', error);
    }

    // ... 繼續啟動伺服器 ...
}
```

### 🛠️ 修正流程

#### **步驟 1：決定修正策略**

有兩種修正方式：

**方式 A：修改參照方（AttributeBonus/WeaponModifier）**
- 適用於：命名不一致、大小寫錯誤
- 修改 `affectedStat` 欄位為正確的屬性 ID

**方式 B：擴充定義方（WeaponStatConfig）**
- 適用於：確實需要新屬性（如 `strength`, `vitality`）
- 在 WeaponStatConfigs 表中新增屬性定義

---

#### **步驟 2：修改 Google Sheets**

1. 打開對應的配置表
2. 根據修正策略修改欄位
3. 儲存變更

---

#### **步驟 3：更新快取**

```bash
# 重新下載 Google Sheets 資料
npm run update-cache  # 或對應的更新快取指令
```

---

#### **步驟 4：重新驗證**

```bash
npx tsx test-scripts/test-config-validation.ts
```

應該看到：
```
✅ 驗證通過！
```

## 整合到 CI/CD

### GitHub Actions 範例

在 `.github/workflows/config-validation.yml` 中：

```yaml
name: Config Validation

on:
  push:
    paths:
      - 'data/google-sheets-cache.json'
  pull_request:
    paths:
      - 'data/google-sheets-cache.json'

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'
          
      - name: Install dependencies
        run: npm install
        
      - name: Validate configs
        run: npx tsx test-scripts/test-config-validation.ts
```

## 驗證結果說明

### ✅ 成功
- `isValid: true`
- 所有參照都有效
- 可以安全部署

### ❌ 失敗（錯誤）
- `isValid: false`
- 有已啟用的配置參照了不存在的項目
- **必須修正才能正常運作**

### ⚠️ 警告
- `isValid: true`
- 有已停用的配置參照了不存在的項目
- 不影響運作，但建議清理

## API 參考

### ConfigValidationService

```typescript
class ConfigValidationService {
    // 完整驗證
    static validateAllConfigs(): ValidationResult

    // 單獨驗證 AttributeBonus
    static validateAttributeBonusConfig(): ValidationResult

    // 單獨驗證 WeaponModifier
    static validateWeaponModifierConfig(): ValidationResult
}
```

### ValidationResult

```typescript
interface ValidationResult {
    isValid: boolean;      // 是否通過驗證
    errors: string[];      // 錯誤列表（已啟用的配置）
    warnings: string[];    // 警告列表（已停用的配置）
}
```

## 常見問題

### Q1：驗證失敗但遊戲還能運行？
**A：** 是的，驗證失敗不會阻止遊戲運行，但會導致：
- 某些加成無法生效
- 某些詞綴無法應用
- 可能產生運行時警告

建議盡快修正配置錯誤。

---

### Q2：應該修改哪一邊的配置？
**A：** 優先修改參照方（AttributeBonus/WeaponModifier），除非確實需要新增屬性到 WeaponStatConfig。

---

### Q3：可以忽略警告嗎？
**A：** 警告針對已停用的配置，不影響運作，但建議清理以保持配置整潔。

---

### Q4：如何新增屬性到 WeaponStatConfig？
**A：** 在 Google Sheets 的 `WeaponStatConfigs` 表中新增一行：

| attributeId | statName | type | category | aliases | description | enabled |
|---|---|---|---|---|---|---|
| strength | 力量 | number | combat | str | 角色基礎力量屬性 | TRUE |

## 最佳實踐

1. **每次修改配置後執行驗證**
   ```bash
   npm run update-cache
   npx tsx test-scripts/test-config-validation.ts
   ```

2. **在開發環境啟動時自動驗證**
   - 在 `main.ts` 中加入驗證邏輯
   - 使用警告而非錯誤，避免阻擋開發

3. **在 CI/CD 中強制驗證**
   - 配置檔案變更時觸發驗證
   - 驗證失敗則阻擋部署

4. **定期審查警告**
   - 清理已停用但有錯誤的配置
   - 保持配置表整潔
