**實施時間**：2025年11月2日  
**分支**：`Colyseus-武器大改`

## 🎯 核心問題

### 原始問題

```typescript
// ❌ 問題：投射物命中時需要回查武器獲取標籤
const attacker = room.getUnitById(bullet.ownerId);  // 如果攻擊者已死亡？
const weapon = attacker?.currentWeapon;              // 如果切換了武器？
const elementTags = weapon?.getElementTags();        // 回查失敗！
```

### 風險
- 攻擊者死亡導致回查失敗
- 攻擊者切換武器導致標籤錯誤
- 多層查找影響性能
- 代碼耦合度高

    ↓

    ↓

    ↓

    ↓

```

**問題**：
- ⚠️ 攻擊者可能已死亡
- ⚠️ 攻擊者可能切換武器
- ⚠️ 多層查找影響性能

### 修改後（攜帶方式）

```
武器攻擊
    ↓

    ↓
AttackResult (攜帶標籤)
    ↓
投射物創建
    ↓
ServerBullet (攜帶標籤)
    ↓
投射物命中
    ↓

    ↓
計算傷害

**優點**：
- ✅ 標籤在攻擊時固定
- ✅ 不受攻擊者狀態影響

## 🎨 設計決策

### 1. 為什麼使用可選欄位？

```typescript
interface AttackResult {
    tags?: string[];  // 可選
}
```

**原因**：向後兼容
- 舊代碼不受影響
- 可以逐步遷移
- 不強制所有地方都提供標籤

---

### 2. 為什麼保留 getAttacker()？

雖然移除了標籤回查，但仍需要 `getAttacker()` 來計算**動態屬性**：

| 屬性 | 是否攜帶 | 原因 |
|-----|---------|------|
| 武器標籤 | ✅ 攜帶 | 攻擊時已確定，不應變化 |
| 元素標籤 | ✅ 攜帶 | 攻擊時已確定，不應變化 |
| 武器詞綴 | ✅ 攜帶 | 攻擊時已確定，不應變化 |
| 攻擊力 | ❌ 查詢 | 動態變化（Buff/裝備） |
| 天賦加成 | ❌ 查詢 | 動態變化（天賦切換） |
| 元素精通 | ❌ 查詢 | 動態變化（天賦/裝備） |

**結論**：
- **固定屬性**（標籤）→ 攜帶
- **動態屬性**（加成）→ 查詢

---

### 3. 為什麼 StatusEffectConfig 也攜帶標籤？

```typescript
interface StatusEffectConfig {
    tags?: string[];      // 🆕
    baseDamage?: number;  // 🆕
}
```

**目的**：支持天賦增強狀態效果

**範例**：
```typescript
// 天賦：火焰精通 +15% 火焰傷害
const talent = {
    affectedTags: ['fire'],
    statType: 'INCREASED',
    statValue: 15
};

// 燃燒效果攜帶 tags
const burnEffect = {
    type: 'burn',
    tags: ['fire', 'damage_over_time'],
    baseDamage: 10,
    duration: 3000
};

// 天賦系統可以增強：10 * (1 + 0.15) = 11.5
```
