# 🎯 攻擊結果結構檢查與優化建議

> **檢查日期**: 2025-01-02  
> **檢查範圍**: AttackResult 接口與標籤系統的整合性

---

## 📋 當前 AttackResult 結構

### 接口定義 (`AttackTypes.ts`)

```typescript
export interface AttackResult {
    success: boolean;
    attackerId?: string;        // 傷害來源
    weaponId?: string;          // 使用的武器
    targetIds?: string[];       // 目標ID列表

    // 傷害信息
    baseDamage: number;
    actualDamage?: number;      // 實際造成的傷害
    isCritical?: boolean;

    // 🆕 狀態效果 (從武器屬性生成)
    statusEffects?: StatusEffectConfig[];

    // 視覺效果
    visualEffects?: VisualEffect[];          // 近戰武器使用
    projectileConfig?: BulletCreateConfig;   // 投射武器使用

    // 失敗原因
    reason?: AttackFailReason;

    // 攻擊數據
    attackData?: {
        position: Vector2;
        direction: Vector2;
        range: number;
        sweepAngle?: number;
        targetPosition?: Vector2;
        supportRadius?: number;
        properties?: PropertyValue[];  // ⚠️ 武器屬性
    };
}
```

## ✅ 當前結構的優點

### 1. 統一的接口設計

```typescript
// ✅ 近戰武器
MeleeWeapon.tryAttack() -> AttackResult

// ✅ 投射武器  
ProjectileWeapon.tryAttack() -> AttackResult

// ✅ 輔助武器
SupportWeapon.tryAttack() -> AttackResult

// ✅ 投射物命中
ProjectileBasic.onHit() -> AttackResult
```

所有武器類型都返回統一的 `AttackResult`，便於 `CombatSystem` 處理。

### 2. 清晰的職責分離

```typescript
// 武器系統 -> AttackResult (攻擊計劃)
{
    success: true,
    baseDamage: 50,
    statusEffects: [{ type: 'burn', duration: 5000 }]
}

// CombatSystem -> DamageSystem (傷害計算)
DamageSystem.calculateFinalDamage(damageInfo)

// DamageSystem -> StatusEffectSystem (狀態效果)
StatusEffectSystem.applyEffect(target, 'burn', config)
```

### 3. 支持狀態效果配置

```typescript
statusEffects?: StatusEffectConfig[]

// 配置驅動，從武器屬性生成
{
    type: 'burn',           // 🏷️ 使用屬性ID
    duration: 5000,
    value: 10,
    chance: 30,
    category: 'debuff'
}
```

## ⚠️ 發現的問題與優化建議

### 問題 1: 缺少標籤信息 ❌

**問題描述**:

`AttackResult` 沒有直接攜帶武器的標籤信息，導致 `DamageSystem` 需要回查武器：

```typescript
// ❌ 當前做法：ProjectileBasic.getElementTags()
private getElementTags(bullet: ServerBullet, gameRoom: GameRoom): string[] {
    const attacker = this.getAttacker(bullet.ownerId, gameRoom);
    const hero = attacker as any;
    const weapon = hero.currentWeapon?.weaponSchema;
    const elementType = weapon.elementType || 'physical';  // 回查武器
    return [elementType];
}
```

**問題**:
- 需要通過 `ownerId` → `attacker` → `weapon` 多層查找
- 如果攻擊者已死亡或離線，無法獲取標籤
- 投射物命中時可能無法正確應用元素加成

**優化建議**:

```typescript
export interface AttackResult {
    // ... 現有欄位
    
    // 🆕 添加標籤信息（POE 風格）
    tags?: string[];              // 武器標籤 ['weapon', 'melee', 'sword', 'fire']
    elementTags?: string[];       // 元素標籤 ['fire', 'elemental']
    
    // 🆕 武器詞綴（用於物理效果判斷）
    modifiers?: any[];            // 武器詞綴 [{ id: 'piercing', ... }]
}
```

**使用範例**:

```typescript
// 武器生成 AttackResult 時攜帶標籤
public override tryAttack(...): AttackResult {
    const stats = this.getFinalStats();
    
    return {
        success: true,
        weaponId: this.weaponId,
        baseDamage: stats.weaponDamage,
        
        // ✅ 直接攜帶標籤
        tags: this.getTags(),              // ['weapon', 'melee', 'sword', 'fire']
        elementTags: this.getElementTags(), // ['fire', 'elemental']
        modifiers: this.getModifiers(),    // [{ id: 'piercing', ... }]
        
        statusEffects: this.getStatusEffects(),
        // ...
    };
}

// DamageSystem 直接使用
const damageInfo: DamageInfo = {
    attacker: hero,
    target: enemy,
    baseDamage: result.baseDamage,
    elementTags: result.elementTags,     // ✅ 直接使用，不需回查
    weaponModifiers: result.modifiers    // ✅ 直接使用
};
```

### 問題 2: properties 欄位冗餘 ❌

**問題描述**:

`attackData.properties` 欄位攜帶了完整的武器屬性，但實際使用場景不明確：

```typescript
attackData?: {
    // ...
    properties?: PropertyValue[];  // ⚠️ 完整的武器屬性列表
}
```

**問題**:
- `PropertyValue[]` 包含大量數據（所有狀態效果、詞綴、加成）
- `AttackResult` 已經有 `statusEffects` 欄位
- 傳遞冗餘數據增加網絡開銷

**優化建議**:

**方案 A: 移除 properties 欄位**

```typescript
// ❌ 移除
attackData?: {
    position: Vector2;
    direction: Vector2;
    range: number;
    // properties?: PropertyValue[];  // 移除
}

// ✅ 使用專用欄位
{
    tags: string[];
    elementTags: string[];
    modifiers: any[];
    statusEffects: StatusEffectConfig[];
}
```

**方案 B: 改為精簡版屬性**

```typescript
attackData?: {
    // ...
    
    // ✅ 只攜帶關鍵屬性
    criticalInfo?: {
        critRate: number;
        critDamage: number;
    };
    
    // ✅ 或使用屬性ID列表
    activePropertyIds?: string[];  // ['burn', 'piercing', 'critical_chance']
}
```

**推薦**: 使用方案 A，通過專用欄位傳遞所需信息。

### 問題 3: StatusEffectConfig 欠缺標籤信息 ⚠️

**問題描述**:

`StatusEffectConfig` 只有基礎欄位，沒有標籤信息：

```typescript
export interface StatusEffectConfig {
    type: string;          // 效果ID
    duration: number;
    value?: number;
    chance?: number;
    direction?: Vector2;
    category: CategoryKey;
    // ❌ 缺少標籤信息
}
```

**問題**:
- 天賦系統需要標籤來判斷是否增強效果
- 例如「火焰精通」應該增強「燃燒」效果的傷害
- 當前需要回查 `StatusEffectDefinitions` 表

**優化建議**:

```typescript
export interface StatusEffectConfig {
    type: string;
    duration: number;
    value?: number;
    chance?: number;
    direction?: Vector2;
    category: CategoryKey;
    
    // 🆕 添加標籤（從定義表複製）
    tags?: string[];       // ['fire', 'ailment', 'elemental']
    
    // 🆕 添加基礎數值（便於計算）
    baseDamage?: number;
    damageScaling?: number;
}
```

**使用範例**:

```typescript
// 武器生成狀態效果時攜帶標籤
private getStatusEffects(): StatusEffectConfig[] {
    return this.fixedProperties.map(prop => {
        const definition = StatusEffectService.getDefinition(prop.id);
        
        return {
            type: prop.id,
            duration: definition.duration * 1000,
            value: prop.value,
            chance: prop.probability,
            category: definition.category,
            
            // ✅ 攜帶標籤
            tags: definition.tags.split(',').map(t => t.trim()),
            baseDamage: definition.baseDamage,
            damageScaling: definition.damageScaling
        };
    });
}

// 天賦系統增強效果
const burnEffect = result.statusEffects.find(e => e.type === 'burn');
if (burnEffect && hasMatchingTags(burnEffect.tags, ['fire', 'elemental'])) {
    burnEffect.value *= 1.15;  // ✅ 火焰精通 +15%
}
```

### 問題 4: elementType 字符串格式不一致 ⚠️

**問題描述**:

`ProjectileBasic.getElementTags()` 使用舊的 `elementType` 字符串：

```typescript
// ❌ 舊系統
const elementType = weapon.elementType || 'physical';  // 單一字符串
const tags = [elementType];
```

但武器配置表已改用標籤系統：

```typescript
// ✅ 新系統
{
    id: 'fire_sword',
    tags: 'weapon,melee,sword,fire',  // 逗號分隔的標籤字符串
}
```

**問題**:
- 新舊系統並存，容易混淆
- `elementType` 只能表示單一元素
- 無法支持混合元素武器（火焰+冰霜）

**優化建議**:

**步驟 1: 在 WeaponSchema 中添加標籤解析**

```typescript
// WeaponSchema.ts
export class WeaponSchema extends Schema {
    @type("string") public weaponId: string = "";
    @type("string") public elementType: string = "";  // ⚠️ 舊欄位，保留兼容性
    
    // 🆕 添加標籤獲取方法
    public getTags(): string[] {
        // 優先使用配置表的標籤
        const config = WeaponConfigManager.getConfig(this.weaponId);
        if (config && config.tags) {
            return config.tags.split(',').map(t => t.trim());
        }
        
        // 向下兼容：從 elementType 轉換
        return this.elementType ? [this.elementType, 'weapon'] : ['weapon'];
    }
    
    public getElementTags(): string[] {
        const allTags = this.getTags();
        const elementTags = allTags.filter(tag => 
            ['fire', 'cold', 'lightning', 'poison', 'physical', 'chaos'].includes(tag)
        );
        
        // 如果是元素傷害，添加通用 'elemental' 標籤
        if (elementTags.length > 0 && !elementTags.includes('physical')) {
            elementTags.push('elemental');
        }
        
        return elementTags;
    }
}
```

**步驟 2: 在 AttackResult 中直接攜帶標籤**

```typescript
// WeaponBasic.ts
protected generateAttackResult(...): AttackResult {
    return {
        success: true,
        weaponId: this.weaponId,
        baseDamage: this.getFinalStats().weaponDamage,
        
        // ✅ 直接從 Schema 獲取標籤
        tags: this.weaponSchema.getTags(),
        elementTags: this.weaponSchema.getElementTags(),
        modifiers: this.weaponSchema.getModifiers(),
        
        statusEffects: this.getStatusEffects(),
        // ...
    };
}
```

**步驟 3: 移除 ProjectileBasic 中的標籤回查**

```typescript
// ProjectileBasic.ts

    // ❌ 移除
    // const elementTags = this.getElementTags(bullet, gameRoom);
    
    // ✅ 直接從 bullet 攜帶的標籤使用

        attacker: attacker,
        target: hitTarget,
        baseDamage: bullet.damage,
        elementTags: bullet.elementTags,      // ✅ bullet 創建時已攜帶
        weaponModifiers: bullet.modifiers     // ✅ bullet 創建時已攜帶
    };

}
```

### 修改 3: WeaponSchema 添加標籤方法

```typescript
// Colyseus/Schema/Weapon/WeaponSchema.ts
export class WeaponSchema extends Schema {
    // ... 現有欄位
    
    /**
     * 🆕 獲取武器完整標籤
     */
    public getTags(): string[] {
        const config = WeaponConfigManager.getConfig(this.weaponId);
        if (config && config.tags) {
            return config.tags.split(',').map(t => t.trim());
        }
        return ['weapon'];
    }
    
    /**
     * 🆕 獲取元素標籤
     */
    public getElementTags(): string[] {
        const allTags = this.getTags();
        const elementTags = allTags.filter(tag => 
            ['fire', 'cold', 'lightning', 'poison', 'physical', 'chaos', 'holy', 'shadow'].includes(tag)
        );
        
        if (elementTags.length > 0 && !elementTags.includes('physical')) {
            elementTags.push('elemental');
        }
        
        return elementTags.length > 0 ? elementTags : ['physical'];
    }
}
```

## 📝 總結

### ✅ 當前結構的優點

1. 統一的 `AttackResult` 接口
2. 清晰的職責分離
3. 支持狀態效果配置

### ⚠️ 主要問題

1. **缺少標籤信息** - 需要多層回查，容易失敗
2. **properties 欄位冗餘** - 攜帶不必要的完整屬性
3. **StatusEffectConfig 欠缺標籤** - 無法應用天賦加成
4. **elementType 格式不一致** - 新舊系統並存

### 🎯 優化重點

1. **在 AttackResult 中攜帶標籤** - 避免回查
2. **在 StatusEffectConfig 中攜帶標籤** - 支持天賦加成
3. **統一使用標籤系統** - 移除 elementType
4. **精簡 attackData** - 移除冗餘的 properties

### 💡 實施建議

- **漸進式重構** - 先擴展接口（向下兼容），再逐步移除舊代碼
- **測試覆蓋** - 每個階段完成後進行測試
- **文檔同步** - 更新相關文檔和註釋
